# How each point of the review was addressed

| # | Review finding | What changed | Where | Proven by |
|---|---|---|---|---|
| 1 | Nothing had run; no database or browser tests | Stack simplified to run on a JupyterHub/GPU server without Docker (SQLite + in-process durable jobs, pre-built UI). Real database, API, executor, training and browser journeys all executed. | whole package | TEST_RESULTS.md: 56 backend tests incl. real LoRA training; Playwright journey; clean install; Python 3.10 + 3.11 |
| 2 | The extract-only gate would send almost every answer to a human | Deterministic validators check each claim: citation validity, equipment-to-value binding in the same table row/sentence, value, unit, sign, range, max/min direction, normal vs startup/shutdown/trip/design, negation, section scope and revision. Correctly cited generated answers are released; the verbatim-extract gate is now only a fallback. | `validators.py`, `review.py`, `executor.py` | `test_validators_review.py` (swapped values, invented tags, wrong unit/limit/condition/negation); `test_good_answer_released_with_server_built_citations` |
| 3 | `reviewer_verdict` defaulted to PASS | Required keyword argument; must be a `Verdict` (a string or omission raises `TypeError`). If the model reviewer is unavailable or its reply cannot be parsed, the answer goes to an engineer. | `review.py` | `test_extract_gate_requires_explicit_verdict`, `test_unavailable_model_reviewer_routes_to_human`, `test_unparseable_model_review_routes_to_human` |
| 4 | Review result lacked spec fields | Result is `{verdict, issues[{code, claim, explanation, evidence_refs, blocking, source}], missing_evidence, suggested_action}`; no confidence percentages. Shown to builders and in the engineer queue. | `review.py`, Review UI | `test_model_reviewer_can_make_stricter_and_result_is_spec_shaped` |
| 5 | Site-wide login bucket (whole plant locked by one person); fixed 1-minute window | No site-wide bucket. Per-account (5) and per-address (30) allowances, then exponential lock 30 s → 15 min; success clears the account counter; the client address comes from `X-Forwarded-For` only when `NEXAGENT_TRUSTED_PROXY=1`. | `security.py`, `api/admin.py` | `test_login_backoff_is_per_account_not_site_wide`, `test_lock_grows_exponentially_and_is_capped` |
| 6a | Same person could approve the answer and its training use | Two-person rule enforced at approval time and again when a dataset version is built. | `datasets.py` | `test_human_review_correction_and_dataset_two_person_rule` |
| 6b | Trainer received only the train split | Export = train + validation; held-out is available only to the separate evaluation step and never written to the training job folder. | `datasets.training_export`, `coordinator.start_job` | `test_dataset_version_splits_export_and_leakage`, `test_real_lora_training_evaluation_and_promotion` |
| 6c | Export dropped hash and classification | Export carries `dataset_sha256` and `classification`; the adapter artifact inherits the classification. | same | same |
| 6d | No minimum split sizes | ≥1 train and ≥1 held-out example required; every group needs an explicit split. | `datasets.build_version` | `test_dataset_version_splits_export_and_leakage` |
| 7a | No HSTS / CSP | CSP, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy on every response; HSTS when served over HTTPS. | `main.py` | `test_security_headers` |
| 7b | `users` table relied on app checks only | Kept (SQLite has no row-level security), but every access decision lives in one module (`policy.py`) and is repeated inside the retrieval SQL and just before release. Documented in SECURITY.md. | `policy.py`, `retrieval.py` | `test_unauthorized_user_cannot_retrieve_or_view` |
| 7c | New project owner could not see existing KBs | Promoting a member to owner grants read/write on all of the project's knowledge bases. | `api/projects.set_member` | exercised in the fixture set-up |

Scope advice from the review was also applied. The build order was: working RAG builder first, then review, then datasets, then training. Fine-tuning is deliberately positioned for style and terminology, and the UI and docs say so.
